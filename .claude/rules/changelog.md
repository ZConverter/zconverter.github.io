## CHANGELOG 작성 규칙 (2026-09-09 추가)

**최상위는 월(月), 그 아래는 접이식 항목 하나씩.** 분류 섹션을 두지 않는다.

```html
## 2026년 9월

<details>
<summary><code>[09-04] [Added&nbsp;&nbsp;] [CLI v3.0.0]</code> <b>recovery monit 실행 출력 예시</b></summary>

- 부연 설명

</details>
```

렌더 결과:

```
▸ [09-04] [Added  ] [CLI v3.0.0]  recovery monit 실행 출력 예시
▸ [09-04] [Changed] [CLI v3.0.0]  backup 7개
▸ [08-28] [Changed] [Site      ]  빌드 환경
```

### 한 줄의 구성

`<code>[MM-DD] [분류] [제품 v버전]</code> <b>제목</b>` — 접두는 `<code>`, 제목은 `<b>`.

| 칸 | 값 | 폭 |
|---|---|---|
| 날짜 | `[09-04]` | 7 (고정) |
| 분류 | `Added` · `Changed` · `Fixed` · `Removed` | **7 로 패딩** |
| 제품 | `API v3.0.0` · `CLI v3.0.0` · `Site` | **10 으로 패딩** |

### ★ 정렬은 `<code>` + `&nbsp;` 로만 된다

**공백으로 맞추려 하지 말 것.** 이 파일은 GitHub 저장소 화면에서만 읽히는데(Jekyll 이 렌더하지 않음),

1. `<summary>` 는 **가변폭 글꼴**로 렌더돼 글자 수를 맞춰도 폭이 안 맞고
2. HTML 이 **연속 공백을 하나로 합친다**

그래서 접두를 `<code>`(고정폭)로 감싸고 부족한 칸을 `&nbsp;` 로 채운다. `Added`·`Fixed` 는
`&nbsp;` 2개, `Changed`·`Removed` 는 0개. `Site` 는 6개.

원본에 `&nbsp;` 가 보이는 것은 감수한 비용이다 — 이걸 공백으로 "정리" 하면 정렬이 깨진다.

### 제목

- **동사를 붙이지 않는다** — `신설`·`갱신`은 분류가 이미 말한다. **명사구로 끝낸다.**
- **개수만 적지 않는다.** 대상을 가리켜야 한다.
  - 문서 1~4개: `backup monitoring-job · monitoring-system`
  - 5개 이상 같은 도메인: `backup 6개`
  - 5개 이상 여러 도메인: `backup·recovery 등 8개`
  - 경로가 없으면 본문 첫 주제문(최상위 불릿)에서 뽑는다. `**Context**`·`**Notes**` 블록은 건너뛴다
- **내부 작업 ID(`FIL-03`·`B1~B32` 등)를 쓰지 않는다** — 제3자가 알 수 없다.

### 그 밖에

- 최신 월이 위, 월 안에서는 **날짜 내림차순**.
- **한 항목은 한 제품만 다룬다.** API·CLI 문서를 함께 고쳤으면 항목을 둘로 나눈다.
- **이모지를 쓰지 않는다** (본 문서 코딩 컨벤션). 하위 호환이 깨지면 제목 끝에
  ` — 하위 버전 호환 X` 를 텍스트로 붙인다.
- `<summary>` 안에는 **인라인 요소만** — `<h3>` 같은 블록 요소를 넣으면 펼침 삼각형이 윗줄로 밀린다.
- **여기는 문서 사이트라 문서 변경이 곧 산출물이다** — 코드 저장소의 "Docs 제외" 규칙은 적용하지 않는다.
  빌드·네비게이션·다운로드 페이지처럼 문서가 아닌 사이트 변경은 제품 칸에 `Site` 를 쓴다.
