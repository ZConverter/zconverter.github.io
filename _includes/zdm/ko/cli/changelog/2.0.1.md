**신규 기능 — `--interactive` 옵션 도입 (`schedule create`, `backup regist`)**

옵션을 하나씩 외우거나 매번 긴 명령을 적지 않아도, 단계별 질문에 답하면서 명령을 완성할 수 있는 대화형 모드가 추가되었습니다.

| 커맨드 | 옵션 | 동작 |
|---|---|---|
| `schedule create` | `--interactive` / `-i` | `type` 을 select prompt 로 선택 → 해당 type 이 요구하는 옵션을 순차 prompt |
| `backup regist` | `--interactive` / `-i` | `server` 등 누락된 필수 옵션을 순차 prompt |

- **혼합 사용 가능**: CLI 옵션으로 이미 입력한 값은 prompt 에서 자동 skip. 누락된 항목만 묻습니다.
- **회귀 안전**: `--interactive` 미지정 시 동작은 기존과 동일.
- 의존성: `@inquirer/prompts` 신규 도입

```bash
# 1) 전부 대화형
zdm-cli schedule create --interactive

# 2) 일부만 미리 입력, 나머지는 대화형
zdm-cli schedule create --type 4 --basic-time 14:00 --interactive
zdm-cli backup regist --jobName daily-bk --partition C: --interactive

# 3) 비대화 (기존 동작 그대로)
zdm-cli schedule create --type 4 --basic-day 1 --basic-time 14:00
```

연관: `schedule create` 의 `type` 필수 → 선택, `backup regist` 의 `server` 필수 → 선택.

**변경 사항 — `backup monit` 출력 개편 (`--log` 옵션 + message 한 줄)**

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 기본 호출 | `[Job Logs]` 섹션 항상 출력 | `[Job Logs]` 섹션 미출력 |
| message 컬럼 | `progressInfo.message` 만 표시 | log 가 있으면 **최신 log 한 줄**을 message 자리에 표시 (작업 진행 상황 즉시 확인 가능) |
| `--log` 옵션 | — | `[Job Logs]` 섹션 표시 토글 (alias `-l`) |
| log prefix | `1: ` `2: ` 숫자 prefix 있음 | prefix 제거, log 본문만 출력 |

```bash
# 기본 — 깔끔한 한 줄 요약
zdm-cli backup monit --job-id 123

# 전체 log 섹션까지 보기
zdm-cli backup monit --job-id 123 --log
```

**변경 사항 — `backup monit` `--server-id` / `--server-name` description 정정**

backup 의 모니터링 대상은 **소스 서버** 인데 기존 description 이 "target server" 라고 표기되어 오해를 유발했습니다.

| 옵션 | 변경 전 description | 변경 후 description |
|---|---|---|
| `--server-id` | `target server ID` | `server ID to monitor (backup source server)` |
| `--server-name` | `target server name` | `server name to monitor (backup source server)` |

- `--help` 출력만 변경 (커맨드 동작은 동일)

**변경 사항 — `backup update` `--schedule` / `--schedule-id` description 보강**

스케줄 입력 양식이 mode(full/inc/smart) 에 따라 다른데 description 에 한 가지 예시만 있어 사용자가 다른 모드의 형식을 추정해야 했습니다. 3개 모드 예시를 모두 명시합니다.

```
--schedule        full/inc → '{"type":4,"basic":{...}}'
                  smart     → '{"type":7,"basic":{...},"advanced":{...}}'

--schedule-id     full/inc → '123'
                  smart     → '{"type":7,"basic":123,"advanced":456}'
```

- `--help` 출력만 변경 (커맨드 동작은 동일)

**변경 사항 — `backup regist` `--mode` 기본값 `full`**

`--mode` 가 필수 옵션이었으나 기본값을 `full` 로 적용하여 미지정 시 자동으로 full 백업으로 동작합니다.

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| `--mode` | 필수 (미입력 시 에러) | 선택, 기본값 `full` |

- `--mode full` 명시 케이스는 기존과 동일하게 동작 (API 동작 동일)

**Fixed — `backup regist --ind` Individual JSON 예시 정정**

`--help` 의 Individual JSON 예시가 실제 API 검증에 실패하는 boolean 형식으로 표시되어 있던 문제를 정정했습니다.

| 필드 | 변경 전 예시 | 변경 후 예시 |
|---|---|---|
| `compression` | `true` | `"use"` |
| `encryption` | `false` | `"not use"` |
| `autoStart` | `true` | `"use"` |

- API 의 zod 검증은 `"use"` / `"not use"` enum 만 허용 — 변경 전 예시 그대로 사용하면 실제 등록이 실패했음
- Notes 라인에 enum 허용 값 / mode 허용 값 함께 명시

**참고 — 빌드 환경 변경 (사용자에게 직접 보이지 않음)**

- `@inquirer/prompts` 가 Node 22 이상에서만 동작하는 API(`util.styleText`) 를 사용하므로 빌드 Node 버전을 v18.20.5 → v22.21.1 로 상향했습니다. 빌드 산출물(SEA 단일 실행 바이너리)이 자체 Node 런타임을 포함하므로 사용자 환경 Node 버전과는 무관합니다.
