**변경 사항 — `schedule create --interactive` 타입별 정밀 분기**

대화형 schedule 생성 시 type 에 따라 의미가 다른 입력 필드를 정확히 분기하여 prompt 합니다.

기존 정적 검증 규칙이 동일 옵션 키에 단일 규칙만 적용해, API 호출 단계에서야 거부되던 케이스를 prompt 단계에서 차단합니다.

| 옵션 | type | 변경 전 | 변경 후 |
|------|------|---------|---------|
| `basic-day` | 4 / 5 (Weekly) | 1~31 정수 csv 강요 | 요일 csv (`mon,wed,fri`) 허용 |
| `basic-day` | 7 / 8 / 10 (Smart basic) | csv 허용 | 단일 요일만 허용 (basic 모드 복수 불가 정책) |
| `basic-day` | 9 / 11 (Smart basic) | csv 허용 | 1~31 단일값 |
| `advanced-day` | 9 / 11 (Smart advanced) | 요일 입력 강요 | 1~31 csv 허용 |
| `basic-week` | 8 / 10 (Smart basic) | csv 허용 | 단일값 |
| `advanced-week` | 8 / 10 (Smart advanced) | 단일값 강요 | csv 허용 |

- prompt 가 요구한 모든 필드는 빈 입력 차단 (이전: `basic-time` 만 차단)
- 비대화 모드(`--interactive` 미지정) 동작은 변경 없음
- prompt 메시지는 한국어 일관 유지

**변경 사항 — `replication delete` / `os-replication delete` 응답 양식 통일**

ZDM API v2.0.2 의 응답 양식 변경에 맞춰 CLI 출력 구조를 `backup delete` / `recovery delete` 와 통일했습니다.

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 응답 섹션 | `[Deleted Job]` + `[Deleted Relations]` | `=== Delete Summary ===` + `=== Job Details ===` |
| Summary 필드 | `replicationInfo`/`history`/`logEvent` 개별 | `basicInfoDeleted` / `detailInfoDeleted` / `historyDataDeleted` / `logDataDeleted` |
| state 표시 | 미표시 | `success` / `partial` / `fail` 명시 |

```
# 변경 후 출력 예시 (--output text)
=== Delete Summary ===
state              : success
basicInfoDeleted   : 1
detailInfoDeleted  : 1
historyDataDeleted : 3
logDataDeleted     : 12

=== Job Details ===
name                : my_replication_job
basicInfo deleted   : Yes
detailInfo deleted  : Yes
historyData deleted : Yes
logData deleted     : Yes
```

- 적용 커맨드: `replication delete`, `os-replication delete`
- `backup delete` / `recovery delete` 출력 양식과 완전 일치

**변경 사항 — `backup monit` message 표시 정책 개선**

작업 모니터링 결과에서 로그가 없을 때 표시되는 message 가 작업 상태에 어울리는 친절한 placeholder 로 바뀝니다.

| 작업 상태 | 변경 전 | 변경 후 |
|---|---|---|
| `Complete` / `completed` | `(no log available)` | `Job completed` |
| `Error` / `failed` | `(no log available)` | `Job failed` |
| `Canceled` / `Canceling` | `(no log available)` | `Job cancelled` |
| `Processing` / `Preparing` / `Scheduled` / `Registered` | `(no log available)` | `No active log` |
| 그 외 / 상태 없음 | `(no log available)` | `-` |

- `--output text` 와 `--output table` 두 형식 모두 동일하게 적용
- `--log` 옵션은 `[Job Logs]` 섹션 표시 여부만 토글 (message 컬럼 동작 변경 없음)
- log 또는 progressInfo.message 가 있는 경우는 기존 동작 그대로 (해당 값 표시)

```
========== Backup Monitoring ==========
Job ID:     123
Status:     Complete
Progress:   100%
Message:    Job completed       # ← 변경 전: (no log available)
=======================================
```
