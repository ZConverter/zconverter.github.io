<summary><strong>v3.0.0</strong> — ZDM-API 3.0.0 대응 / recovery image-regist·backup image list 신설 / 출력 스트림 분리 / 필드별 오류 표시 복구</summary>

ZDM-API 3.0.0 의 응답 형식 변경에 대응했습니다. **API 버전과 무관하게 동작하므로 업그레이드 순서를 맞출 필요가 없습니다** — 구버전 API 와도 그대로 동작합니다.

---

**신규 — `recovery image-regist`**

Source 서버 없이 backup image 파일명만으로 복구 작업을 등록합니다. Source 서버가 ZDM 에서 삭제된 뒤에도 이미지가 저장소에 남아 있으면 복구할 수 있습니다.

```bash
zdm-cli recovery image-regist \
  --backup-file "server01_ROOT_0262.ZIA,server01_boot_0262.ZIA" \
  --target "t-rocky9_192.168.3.104" \
  --platform oci --mode full --repository-id 9
```

자세한 옵션은 [recovery image-regist](/zdm/ko/cli/3.0.0/docs/recovery/image-regist) 참조.

---

**신규 — `backup image list`**

`recovery image-regist` 의 `--backup-file` 에 넣을 **이미지 파일명을 찾을 방법이 없던 문제**를 해결합니다. 저장소에 저장된 backup image 파일 목록을 조회합니다.

```bash
zdm-cli backup image list --server web01 --names-only
```

- 모든 center / 여러 center / 특정 center(기본값은 config 의 `zdm.id`) / 특정 center 의 특정 저장소, 네 가지 범위로 조회할 수 있습니다.
- `--names-only` 옵션은 파일명만 콤마로 이어 한 줄로 출력합니다 — `recovery image-regist --backup-file` 값으로 그대로 붙여 쓸 수 있습니다.
- 저장소마다 데몬이 직접 스캔하므로 시간이 걸립니다. `--repository-id` 로 저장소 하나로 좁히면 빨라집니다.

자세한 옵션은 [backup image list](/zdm/ko/cli/3.0.0/docs/backup/image-list) 참조.

---

**표시 변경 — 결과 헤더의 추적 ID**

명령 결과 헤더에 표시되는 식별자가 `requestID` 에서 `traceId` 로 바뀝니다.

- **이전**: `* Recovery Registration Result [requestID: 550e8400-...]`
- **이후**: `* Recovery Registration Result [traceId: a1b2c3d4e5f60718293a4b5c6d7e8f90]`

이 값은 서버 로그의 추적 ID 와 같습니다. 장애 문의 시 함께 전달하면 원인 확인이 빨라집니다.

---

**동작 변경 — 출력 스트림 분리 (스크립트 작성 시 확인 필요)**

화면에 보이는 모습은 그대로지만, 표준출력(stdout)과 표준에러(stderr)를 무엇으로 채울지가 바뀝니다. 결과를 파이프나 리다이렉트로 받아 처리하고 있었다면 아래 내용을 확인하세요.

- **진행 메시지가 표준에러로 나갑니다.** `* Requesting ...` / `* ... completed (96ms)` 같은 진행 상황 표시가 이제 stderr 로 나갑니다. 화면에 보이는 순서·모습은 같지만 `2> /dev/null` 로 끌 수 있고, 표준출력을 파이프로 넘겨도 결과 데이터에 섞이지 않습니다.
- **`--o json` 의 표준출력이 순수 JSON 이 됩니다.** `zdm-cli ... --o json | jq` 가 그대로 동작합니다. `config show` / `schedule create` 가 JSON 앞에 찍던 설정 파일 경로 같은 평문도 사라졌습니다 (해당 안내는 진행 메시지 쪽, 즉 stderr 로 옮겨갔습니다).
- **색상은 터미널에 출력할 때만 붙습니다.** 결과를 파일로 저장하거나 파이프로 넘기면 ANSI 색상 코드가 섞이지 않습니다. `NO_COLOR` 환경변수를 설정하면 터미널에서도 강제로 끌 수 있습니다.
- **스크립트를 쓰고 계셨다면**: 표준출력에서 진행 메시지를 읽고 있었다면 영향이 있습니다 (이제 stderr 로 나갑니다). 실패 시 응답 JSON 은 이전과 동일하게 표준출력에 그대로 나오며, 성공/실패 판별은 (표준출력 내용이 아니라) 종료 코드로 하는 것을 권장합니다.

---

**수정 — 필드별 검증 오류가 표시되지 않던 문제**

요청 값이 잘못됐을 때 **어떤 필드가 왜 잘못됐는지가 표시되지 않고** 일반 오류 문구만 나오던 문제를 고쳤습니다.

- **이전**: `Request body validation failed.` (어느 필드인지 알 수 없음)
- **이후**: 필드 이름과 사유가 함께 표시됨

API 3.0.0 이 검증 상세의 위치를 바꿨는데 CLI 가 이전 위치만 보고 있어 생긴 문제입니다. 이제 두 위치를 모두 확인하므로 구버전 API 와도 정상 표시됩니다.

---

**복구 등록 시 주의 — 파티션 매핑 규칙 변경**

ZDM-API 3.0.0 부터 **하나의 대상 파티션은 같은 원본 파티션의 이미지를 최대 1장만 받습니다.** 같은 파티션의 이미지 두 장을 한 대상에 지정하면 등록이 거부됩니다.

같은 원본의 이미지를 여러 장 쓰려면 서로 다른 대상 파티션에 1장씩 배정하세요. 이 배치는 3.0.0 부터 허용됩니다.
