<summary><strong>v3.0.0</strong> — ZDM-API 3.0.0 대응 / recovery image-regist 신설 / 필드별 오류 표시 복구</summary>

ZDM-API 3.0.0 의 응답 형식 변경에 대응했습니다. **API 버전과 무관하게 동작하므로 업그레이드 순서를 맞출 필요가 없습니다** — 구버전 API 와도 그대로 동작합니다.

---

**신규 — `recovery image-regist`**

Source 서버 없이 backup image 파일명만으로 복구 작업을 등록합니다. Source 서버가 ZDM 에서 삭제된 뒤에도 이미지가 저장소에 남아 있으면 복구할 수 있습니다.

```bash
zdm-cli recovery image-regist \
  --backup-file "server01_ROOT_0262.ZIA,server01_boot_0262.ZIA" \
  --target "t-rocky9_192.168.3.104" \
  --platform oci --mode full --repository-id 9
```

자세한 옵션은 [recovery image-regist](/zdm/ko/cli/3.0.0/docs/recovery/image-regist) 참조.

---

**표시 변경 — 결과 헤더의 추적 ID**

명령 결과 헤더에 표시되는 식별자가 `requestID` 에서 `traceId` 로 바뀝니다.

- **이전**: `* Recovery Registration Result [requestID: 550e8400-...]`
- **이후**: `* Recovery Registration Result [traceId: a1b2c3d4e5f60718293a4b5c6d7e8f90]`

이 값은 서버 로그의 추적 ID 와 같습니다. 장애 문의 시 함께 전달하면 원인 확인이 빨라집니다.

---

**수정 — 필드별 검증 오류가 표시되지 않던 문제**

요청 값이 잘못됐을 때 **어떤 필드가 왜 잘못됐는지가 표시되지 않고** 일반 오류 문구만 나오던 문제를 고쳤습니다.

- **이전**: `Request body validation failed.` (어느 필드인지 알 수 없음)
- **이후**: 필드 이름과 사유가 함께 표시됨

API 3.0.0 이 검증 상세의 위치를 바꿨는데 CLI 가 이전 위치만 보고 있어 생긴 문제입니다. 이제 두 위치를 모두 확인하므로 구버전 API 와도 정상 표시됩니다.

---

**복구 등록 시 주의 — 파티션 매핑 규칙 변경**

ZDM-API 3.0.0 부터 **하나의 대상 파티션은 같은 원본 파티션의 이미지를 최대 1장만 받습니다.** 같은 파티션의 이미지 두 장을 한 대상에 지정하면 등록이 거부됩니다.

같은 원본의 이미지를 여러 장 쓰려면 서로 다른 대상 파티션에 1장씩 배정하세요. 이 배치는 3.0.0 부터 허용됩니다.
