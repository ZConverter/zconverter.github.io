#### v3.0.1

라이선스 관련 검증이 빠져 있던 버그 3건을 고치고, 토큰 발급 횟수 제한의 기본값을 올렸습니다. 함께 **실행 파일에 내장된 Node.js 와 라이브러리를 보안 패치 버전으로 교체**했습니다. 응답 형식은 v3.0.0 과 같습니다.

> **v3.0.0 이하를 쓰고 있다면 교체를 권장합니다** — v3.0.0 이하 실행 파일에는 2026-10-21 Node.js 보안 패치가 적용되지 않은 Node.js 22 가 들어 있습니다.

> **연동 시 확인** — 아래 라이선스 관련 세 경우는 v3.0.0 까지 **성공으로 처리되던 요청이 이제 실패합니다.**
> 원래 거부됐어야 할 잘못된 등록을 막는 수정입니다. 해당 순서로 호출하던 연동 코드는 대응 방법을 확인하세요.

---

**Bugfix — 다른 ZDM 용으로 발급된 라이선스 등록 거부**

- `POST /licenses` — 라이선스 키가 `center` 로 지정한 ZDM 의 UUID 로 발급된 것이 아니면 **400 `LICENSE-ERROR-12`** 로 거부합니다. 종전에는 UUID 가 달라도 등록됐습니다.
- 라이선스 키로 해석되지 않는 값을 보내면 **400 `LICENSE-ERROR-09`** 를 반환합니다.
- 대응: 라이선스를 발급받을 때 등록할 ZDM 의 UUID(`GET /zdms` 응답의 `id.machine`)를 그대로 사용하세요. UUID 는 대소문자·중괄호까지 일치해야 합니다.

**Bugfix — 이미 등록된 라이선스의 중복 등록 거부**

- `POST /licenses` — 같은 키가 이미 등록돼 있으면 **409 `LICENSE-ERROR-11`** 을 반환합니다. 종전에는 같은 라이선스가 여러 번 등록됐습니다.
- 대응: 409 를 받으면 이미 등록된 상태이므로 재시도하지 않아도 됩니다. 등록 여부는 `GET /licenses/key/:key` 로 확인할 수 있습니다.

**Bugfix — 라이선스가 할당되지 않은 서버의 backup 등록 거부**

- `POST /backups` — 대상 서버에 라이선스가 할당돼 있지 않으면 **400 `LICENSE-ERROR-13`** 으로 거부합니다. `server` 와 `individual[].server` 로 지정한 서버를 모두 검사하며, 메시지에 라이선스가 없는 서버 이름을 나열합니다.
- 대응: `PUT /licenses/assign` 으로 라이선스를 먼저 할당한 뒤 backup 을 등록하세요. 이미 등록돼 있는 backup 작업에는 영향이 없습니다.

**동작 변경 — 토큰 발급 횟수 제한 기본값 20 → 100**

- `POST /token/issue` — IP 별 발급 시도 제한의 기본값을 **15분당 20회에서 100회**로 올렸습니다. 인증에 성공한 발급도 횟수에 포함되므로, 자동화 작업이 토큰을 반복 발급하다 429 `RATE-LIMIT-01` 에 걸리던 문제를 줄이기 위한 조정입니다.
- 서버 실행 환경에서 `RATE_LIMIT_TOKEN_MAX` 를 지정했다면 그 값이 그대로 우선합니다. 제한을 더 좁히려면 이 값을 낮추세요.

**보안 — 내장 Node.js 를 22 에서 24.22.1 로 교체**

- 실행 파일에 들어 있는 Node.js 런타임을 **v22.21.1 → v24.22.1** 로 올렸습니다. 2026-10-21 Node.js 보안 릴리스의 패치가 반영된 버전입니다.
- 지원 서버 OS 범위는 v3.0.0 과 같습니다(Linux x64).
- 실행 파일 크기가 약 109 MB 에서 약 112 MB 로 늘었습니다.

**보안 — 서버가 사용하는 라이브러리의 취약점 수정**

실행 파일에 포함되는 라이브러리를 같은 메이저 버전 안에서 보안 패치 버전으로 올렸습니다. 엔드포인트 · 요청 · 응답은 바뀌지 않습니다.

| 영역 | 라이브러리 | 수정된 문제 |
|---|---|---|
| 토큰 인증 | jsonwebtoken 9.0.3 | 토큰 서명 검증 결함 |
| DB 접속 | mysql2 3.24.6 | 접속 과정에서 DB 비밀번호가 평문으로 전송될 수 있는 문제, 압축 응답 처리 시 메모리 과다 사용 |
| 요청 처리 | express 4.22.3 | 요청 본문 크기 제한 우회, 경로 · 쿼리 해석의 과부하(DoS), 프록시 경유 시 클라이언트 IP 위조 |
| 파일 업로드 · 요청 검증 | express-openapi-validator 5.6.2 | 잘못된 형식의 업로드 요청으로 서버가 중단될 수 있는 문제 |
| 요청 검증 | zod 4.6.7 | 큰 배열 · 객체 검증 시 메모리 고갈 |
| 요청 횟수 제한 | express-rate-limit 8.7.1 | 일부 IP 표기의 해석 차이 |

- 잘못된 형식의 업로드 요청은 계속 **400** 으로 응답하며, 이후 요청도 정상 처리됩니다.
